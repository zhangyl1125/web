## 入口与管理

- `/awards` 与 `/awards/:id` 使用 `hackhub-app/src/pages/AwardManagement.tsx`，提供评选活动与管理入口，替代不相关的旧业务页面。
- `/committee` 提供已分配评委的活动入口，进入相应活动进行评分。
- 评分与排名页继续按对应活动加载数据；后台排名和逐评委明细仅向具有管理权限的用户开放。
- 全局侧栏与路由清理不相关的组织应用入口，旧入口不再暴露与评选无关的管理页面。
- 公开首页、登录、注册和应用页头复用真实 Bosch 品牌组件 `hackhub-app/src/components/Layout/AwardBrand.tsx`。

## 规则与明确假设

以下员工投票说明于 2026-09-14 按本地代码更新，仅修改文档，未修改代码或核实线上版本。其他功能及下方验证结果保留原交接记录，不表示本次重新验证。

- 当前投票额度：每人、每个评选、每赛道最多投 4 票，本部门最多 2 票，其他部门合计最多 2 票。两组额度独立，各可投 0、1 或 2 票，不能互相挪用；不要求投满，也没有跨部门占比校验。本部门2票、其他部门0票允许，其他部门3票不允许。
- 当前操作流程：先将候选人加入本地票篮，点击 `Submit` 后正式提交；每条候选提名最多投1票，重复提交不重复计票。已提交选票计入后续额度；从账号菜单进入 `My voting records` 删除记录后可重新选择并提交，撤票不限制先后顺序。一次提交整体成功或回滚，失败保留票篮。
- 中文提示已知差异：页面仍有“点赞后自动保存”“再次点击即可取消”等旧提示；当前点击已提交候选人只打开投票记录，不能把本地票篮保存解释为正式提交。本次未修改前端文案。
- 当前未实现的投票门槛：`VoteIdeaUseCase` 的投票、提交、删除记录及清空方法未检查候选人审核通过状态（新增投票时），也未校验投票阶段、活动关闭状态或起止时间。页面时间安排不等于后端会到期锁定提交或撤票。
- 后端冻结既有提名的被提名人身份，防止投票后替换身份绕过部门限制；投票与评分等相关写入使用锁约束并发。部门识别优先使用账号非空 `orgCode`，缺少时依次通过邮箱前缀、姓名唯一匹配BD名册。
- 部门取 Org. code 第一个 `-` 之前的前缀，例如 `BD/DPA-SRE3` 属于 `BD/DPA`，`BD/BA-AP` 属于 `BD/BA`。被提名人与提名提交人应区分，以被提名人的部门进行判断。
- Behavior Demonstration 权重 70%，Business Impact 权重 30%。沿用现有系统的 **1–10 整数**评分范围；材料中的“≤4”按 1–4 实现。
- 两项评分与推荐意见/评论通过同一个评价请求提交，避免只写入一半。只有获分配的组委会成员可以提交评分；管理人员未获分配时可查看资料但不能替代评委评分。
- 单评委总分 = 行为示范分 × 70% + 业务影响分 × 30%。多评委案例总分为所有完整评价的加权总分的算术平均值，不计入未完整评分。员工投票数单列，不混入组委会总分。
- 同分共享名次，采用竞赛排名（如 1、1、3）；未评分案例显示“Not scored”，不参与排名。管理员可按赛道筛选、查看每位评委的两项分数与评论、导出汇总 CSV。
- 照片上传成功后，一次创建请求同时提交个人资料、照片、证据链接和 submitted 状态；不再先创建案例再追加更新，避免产生缺少个人信息的已创建案例。
- 提名资料保存于既有附件结构的 `type: 'nomination'` 元数据中，包含被提名人身份、姓名、职位及提名 HoD；评分页面同时呈现 Org. code 与证据链接。

投票实现依据及未实现项详见[投票规则核查](voting-review-2026-09-08.md)。
